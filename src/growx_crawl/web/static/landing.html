Capabilities

Three systems, one server

Collection, search and extraction share one SQLite store, so everything you crawl is searchable and queryable without another fetch.

  1. 01

    Crawling that gets through

    Start with plain HTTP and escalate to headless Chromium or a stealth browser only when a page needs it. Spider a site up to five levels deep or batch a hundred URLs at once.

    Auto-escalation · Multi-page spider · robots.txt controls

  2. 02

    Search over everything you've crawled

    Every stored page goes into a full-text index with BM25 ranking and link-based authority, returning highlighted snippets without calling out to a search provider.

    SQLite FTS5 · BM25 ranking · Highlighted snippets

  3. 03

    Structured output, not raw HTML

    Pull fields with CSS or XPath, re-query stored snapshots later, and render screenshots, PDFs and SEO audits from the same pages. Export to JSON or CSV.

    CSS & XPath · Screenshots & PDF · SEO audit

API

Plain HTTP and JSON

Authenticate with a bearer key and call the endpoints on your own instance. No SDK required.

Full reference
  • POST
    /v1/scrape

    Fetch one page and return its metadata, headings, links and text.

  • POST
    /v1/crawl

    Start an async multi-page crawl and poll it by job ID.

  • POST
    /v1/extract

    Return named fields from a page using CSS or XPath selectors.

  • GET
    /v1/search?q=…

    Query the full-text index of stored pages.
